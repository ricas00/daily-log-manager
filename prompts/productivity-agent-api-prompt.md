# Build task: read-only "Agent API" for the Productivity Tracker

## What you're building
A small, purpose-built, read-only REST API on the existing Productivity Tracker backend.
An external AI agent (headless, plain HTTPS + curl) fetches per-day work data to compile a
personal daily activity log. The agent needs **everything about a given day in one compact
JSON call**.

Repo: `ricas00/Productivity-Tracker-V2.0` (you have local access; work in `backend/`,
`frontend/`, `docker-compose.yml` at the repo root).

The existing app (React 18 + FastAPI + SQLite, Docker Compose, nginx proxy, behind Cloudflare,
production at `https://productivity.lmsg.pt`) must keep working 100% unchanged.

## Why a new API instead of reusing existing endpoints
- The agent needs a *day bundle* (sessions + per-area totals + daily target + target-met) in a
  single call; today that takes multiple calls plus client-side aggregation.
- Security: the agent must **never** use the app's login password or a user JWT. It gets its own
  scoped, read-only token that works nowhere else.
- The user's log "day" is not the calendar day: it runs from 06:00 to 06:00 (see `cutoff` below).

## The day cutoff (core concept — get this right)
The consuming user's "day" starts at **06:00 local time**, not midnight (they sleep 03:00–04:00).
Log day D = local time window **[D 06:00, D+1 06:00)**.

- `day` and `range` take an optional `cutoff` query param (`HH:MM`, validated, default `"00:00"`).
- `cutoff=00:00` (default): exactly the app's existing midnight semantics (select on the `date`
  column) — zero behavior change for any consumer that doesn't pass it.
- `cutoff != 00:00` (e.g. `06:00`): select sessions whose **`created_at` (naive UTC) converted to
  the `TIMEZONE` env var** falls in `[date cutoff, date+1 cutoff)` (local). Compute this with
  `zoneinfo` — never hardcode UTC offsets (DST!).
  - Returned sessions' `date` COLUMN may be the *next* calendar day for late-night sessions
    (e.g. saved 02:00 → `date`=D+1 but it belongs to log day D). The window is authoritative;
    the column is metadata.
  - A session whose work span straddles the cutoff is attributed **whole** to the day in which it
    was saved (`created_at`). Do NOT split sessions.
- `target_minutes` = `target_daily_minutes` of the week (per `get_config_for_week`) containing
  `date`; `target_met` = `target_minutes > 0 AND total_minutes >= target_minutes`, computed over
  the window's sessions.
- `week` and `streak` keep midnight semantics (they mirror the app's own UI reports). Document
  that explicitly.

## Authentication (must be exactly this)
- New env var `AGENT_API_TOKEN`: long random string, generated by the USER on the production host
  with `python3 -c "import secrets; print(secrets.token_urlsafe(48))"`.
- The client sends it as header **`X-Agent-Token: <token>`** — NOT `Authorization: Bearer`, so it
  can never be confused with or exchanged for a user JWT.
- Compare with `hmac.compare_digest` (constant-time).
- If the env var is unset or empty: every `/v1/log/*` path returns **404** (the feature stays
  hidden until provisioned).
- If set but the header is missing/wrong: **401** `{"detail":"Unauthorized"}` — the SAME body for
  missing and wrong (no guessing oracle). Log a warning with client IP + path; NEVER log the token.
- The token grants GET on `/v1/log/*` only. It must not authenticate any other endpoint
  (structurally true since it's a different header — do not add it as a fallback to the Bearer
  JWT anywhere).
- No cookies, no new CORS entries, no new public write paths.

## Endpoints (all GET; dates are `YYYY-MM-DD`; bad date strings → FastAPI 422)

### `GET /v1/log/day?date=YYYY-MM-DD[&cutoff=HH:MM]` (defaults: date = local today, cutoff = `00:00`)
```json
{
  "date": "2026-09-01",
  "weekday": "Tuesday",
  "total_minutes": 245,
  "target_minutes": 300,
  "target_met": false,
  "session_count": 5,
  "top_area": "FBA",
  "by_area": [{"area": "FBA", "minutes": 120, "color": "#f59e0b"}],
  "sessions": [
    {"id": 123, "minutes": 90, "area": "FBA", "note": "restock audit", "created_at": "2026-09-01T09:12:00Z"}
  ]
}
```
- `top_area` = area name with the most minutes in the window; `null` when there are no sessions.
- `by_area` sorted by minutes desc; `sessions` sorted by `created_at` asc.

### `GET /v1/log/range?date_from=YYYY-MM-DD&date_to=YYYY-MM-DD[&cutoff=HH:MM]`
```json
{"days": [ <day objects, same shape as above — one per day from date_from to date_to INCLUSIVE,
           including zero entries (total 0, no sessions, top_area null) for days with no activity> ]}
```
- `date_from > date_to` → 422. More than 366 days → 422.

### `GET /v1/log/areas`
```json
{"areas": [{"id": 2, "name": "FBA", "color": "#f59e0b"}]}
```
Active areas only.

### `GET /v1/log/week?week_start=YYYY-MM-DD` (must be a Monday, else 422; midnight semantics)
```json
{
  "week_start": "2026-08-31",
  "week_end": "2026-09-06",
  "target_daily_minutes": 300,
  "is_inherited": false,
  "totals": {"minutes": 1500, "days_worked": 5, "days_met": 4},
  "by_area": [
    {"area": "FBA", "minutes": 600, "goal_minutes": 420, "goal_met": true}
  ]
}
```
`goal_minutes`/`goal_met` are `null`/`false` when that area has no goal for the week.
`days_met` = days whose total reached `target_daily_minutes`.

### `GET /v1/log/streak`
Existing `StreakOut` shape: `{current_streak, longest_streak, today_met, target_today_minutes, today_minutes}`.

Timestamps: `created_at` is stored naive UTC — serialize as ISO 8601 with a `Z` suffix.

## Security checklist (all mandatory)
- [ ] Token lives only in `.env` (gitignored). `.env.example` gets only the commented template.
      The real token is never committed, never logged, never echoed in any response body.
- [ ] Constant-time comparison.
- [ ] 404 when unprovisioned, 401 when the token is invalid; identical 401 body for missing vs wrong.
- [ ] Read-only: no state mutation anywhere under `/v1/log`; no new tables; no schema migration.
- [ ] Existing endpoints keep exact behavior (React app unaffected — no changes to auth, sessions,
      stats, timer, export, goals, week-config).
- [ ] Optional (only if trivial): in-memory rate limit for the agent token (e.g. 120 req/min →
      429 with `Retry-After`).

## Tests (pytest, `backend/tests/`; follow existing test setup)
1. `AGENT_API_TOKEN` unset → `GET /v1/log/day` → 404.
2. Token set, no header → 401; wrong header → 401 (same body).
3. Valid header → 200; assert the FULL day object shape (every field present, correct types).
4. Seed sessions across 3 days + work areas: day aggregation correct (totals, `by_area`,
   `top_area`, session ordering); a zero day → total 0, empty sessions, `top_area` null.
5. **Cutoff (DST-safe: compute instants with `zoneinfo`, don't hardcode UTC offsets):** seed a
   session whose `created_at` is 30 minutes *before* local midnight (i.e. local 23:30, the last
   half hour of day D). With `cutoff=06:00` it belongs to log day D; a session saved at local
   02:00 on D+1 also belongs to log day D. With the default `cutoff=00:00` behavior is
   unchanged (midnight, `date`-column semantics).
6. `range`: includes zero days, sorted; `date_from > date_to` → 422; >366 days → 422;
   malformed date or malformed cutoff → 422.
7. `week`: non-Monday `week_start` → 422; seeded week totals/goals correct.
8. The agent token does NOT authenticate `/sessions` (request with only `X-Agent-Token` → 401/403).
